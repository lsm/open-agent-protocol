# Validator rules: models and providers (0006, 0014, 0028, 0035)

Every diagnostic the validators raise about the session model catalog, the
provider descriptors it publishes, the core model switch and live provider
attachment, traced to the decision text that requires it. Rows follow the
shared format in this directory's README. An id is the decision's heading
anchor, with `/n` where one heading carries several checks. Go and Zig name the
function holding the check (`go/validation/` and `zig/src/validation/`). Rust
has no catalog, switch or attach checks yet, so its column is `—` throughout.

Where the two trees disagree, the row still records the rule the decision
states, and the disagreement is listed under OPEN-0006, OPEN-0014 and OPEN-0028
in [`research/validator-divergences.md`](../../research/validator-divergences.md).

The remaining 0006 headings bind the hub and the Go API rather than a trace:
"A served catalog travels with the revision that governs it" (the hub refuses a
listing with no revision or a foreign scope, pinned by `serve` tests), "The open
response is the state document, so the daemon sends it whole", and
"`adapter.ModelLister` is optional and discovered by type assertion". None is a
validator rule. The open response's `current_model_id` is still read: it is
the session default a per-run selection must not move, which Decision 0005's
group judges (fixture models-open-response-guards-the-default,
`unapplied_control`).
